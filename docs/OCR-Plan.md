## v2.0 技术方案：截图识别已开副词条

> 状态：设计方案，尚未实现。引擎选型、性能参数和支持范围需通过真实截图与打包验证。

> 首版范围已收敛，以 [代码实施方案](OCR-Implementation-Plan.md) 为准：只识别开孔过程中已开 1～4 条的固定区域，全部结果预览确认，不接入洗炼；提供透明度、置顶及框选前自动最小化。实时监测、全局快捷键、全屏定位和自动应用均为后续能力，下文保留为总体设计参考。
>
> 分发要求：Windows 11 x64 同时提供整合单文件 EXE 与 EXE＋依赖目录两种发行包；macOS Apple Silicon 提供内置依赖的 `.app`。三种产物均随包提供 OCR 运行库和模型，离线可用，无需用户安装 Python 或单独启动 OCR 工具。

### 1. 目标与范围

- 用户不需要上传图片，通过按钮或快捷键截取游戏画面，识别已经解锁的副词条名称与数值，自动录入区域 2。
- 提供点击识别和可选的实时监测；二者复用截图、OCR、校验和回填链路。
- 保留手动录入；OCR 不可用不能影响现有评分、开孔建议和洗炼分析。
- 首版只识别副词条，不自动修改 Cost、主词条、权重、目标分数或材料预算。识别后仍按当前手动设置计算，并在界面说明。
- 增加窗口透明度滑块，方便对照游戏画面；透明不等于点击穿透，也不能解决截图遮挡问题。
- 所有识别在本机执行，不上传截图，不读取游戏内存，不向游戏进程注入代码。

### 2. 交互设计

区域 2 增加「截图识别」「设置识别区域」「实时监测」及识别状态。

#### 点击识别

1. 首次使用框选游戏中的完整副词条列表区域，包括未解锁槽位，保存所属屏幕及区域。
2. 后续点击按钮直接截取该区域，不再重复框选或导入图片。
3. 识别完整、无歧义且通过校验时自动替换当前副词条；否则展示截图、原始文字和待校正项目，用户确认后应用。
4. 截图失败、无文字或无法确认列表完整时保留原输入，并明确提示原因。
5. 提供快捷键触发；游戏在前台时触发需要系统级全局快捷键，不能仅使用窗口内快捷键。注册失败或冲突需提示，按钮仍可使用。

#### 实时监测

- 默认关闭，用户主动开启；重新启动应用不自动恢复运行中的监测。
- 定时截取小区域，只有画面发生明显变化并稳定后才执行 OCR。
- 连续两次独立截图的识别结果一致、完整且校验通过后才自动应用；相同结果不重复回填或计算。
- 无效结果不覆盖现有数据；显示「识别未更新」及最后成功更新时间，避免旧数据被误认为最新结果。
- 手动修改副词条、清空输入、打开校正窗口或重新框选时暂停监测，用户明确恢复后继续，避免反复覆盖。
- 提供「监测中／识别中／暂停／待确认／失败」状态与暂停入口。

#### 全屏识别与区域识别的边界

- 首版采用“选择一个屏幕上的固定区域”，不直接把整个桌面的全部文字当作副词条解析。
- 后续可增加“点击识别全屏”：先在选定屏幕定位声骸详情面板，再裁剪副词条区域，最后执行同一识别链路。
- 全屏出现多个候选面板或不能确定列表边界时，要求选择区域，不自动猜测。跨屏桌面扫描不列入首版。
- 跟随游戏窗口、自动定位面板和固定区域是不同能力，前两项在区域识别稳定后再实现。

### 3. 技术架构与选型

```text
按钮 / 全局快捷键 / 定时变化检测
                ↓
截图与区域裁剪 → 画面稳定性检查
                ↓
本地 OCR：文字、坐标、置信度
                ↓
名称与数值配对 → 合法档位与完整性校验
                ↓
无歧义：自动应用 / 有疑点：用户校正
                ↓
批量更新区域 2 → 调用一次 calculate()
```

| 层次       | 职责与建议                                                                               |
| ---------- | ---------------------------------------------------------------------------------------- |
| 截图与框选 | 优先验证 Qt 的 `QScreen.grabWindow()`、`QImage` 与框选遮罩，避免先引入额外截图库         |
| 图像预处理 | 裁剪、适度放大、按样本验证对比度处理；不默认做可能损失小数点的强二值化                   |
| OCR        | 优先验证 RapidOCR + ONNX Runtime；PaddleOCR 作为对照，按准确率、耗时、平台与包体成本定型 |
| 词条解析   | 独立于 GUI 和 OCR 引擎，负责行配对、名称别名、单位、档位、重复与完整性检查               |
| GUI 控制   | 管理任务、版本、状态、校正窗口及批量回填，不在计算算法中嵌入 OCR                         |
| 配置       | 使用独立、带版本的本地识别配置，不混入权重方案库                                         |

OCR 依赖和模型延迟加载，实例在识别工作队列内复用。先验证首版 Windows/macOS 目标架构及 Python、NumPy 的兼容范围，再确定依赖版本；不能直接假设候选引擎支持现有全部环境。

### 4. 解析与数据契约

以 [词条配置](config/echo-stats.json) 为唯一档位来源，不复制维护另一份数值表。

OCR 中间结果保留文本、边界框、置信度；解析结果保留原始行、候选 `stat_id`、数值、匹配档位及问题列表。跨线程传递结构化数据和独立图像快照，不传递控件。

最终回填沿用现有 `sub_stats` 数据格式，例如：

```json
[
  {"name": "crit_rate", "value": 10.5},
  {"name": "crit_dmg", "value": 21.0},
  {"name": "atk_pct", "value": 8.6}
]
```

其中 `10.5` 表示 `10.5%`，而不是 `0.105`。

校验规则：

- 根据坐标配对名称与数值，避免跨行拼接；按画面顺序保留词条。
- 使用明确的游戏文字别名映射名称，统一空格及全角符号；模糊匹配只提供候选，不直接自动应用。
- 区分固定生命／攻击／防御和相应百分比属性。百分号缺失时不能只凭数值猜类型。
- 数值必须匹配该词条的配置档位，最多五条且类型不重复。
- 小数点疑似缺失、单位不明或近似档位只标记待确认，不静默修正为最近档位。
- 不能因为主词条或小词条存在同名属性，就排除合法副词条；应通过列表位置和边界排除非副词条文字。
- 必须检查所有可见已开行都有对应结果。识别到三条合法词条不代表实际只有三条；置信度高也不代表没有漏行。
- 在完整性规则经过真实样本验证前，结果默认进入确认界面。零条状态首版要求用户确认，不能把“无文字”直接应用成空列表。

### 5. 异步与回填一致性

参考 [现有 GUI](src/echo_gui.py) 的 `QRunnable`、信号和版本机制，但 OCR 使用独立串行队列，不占用策略／洗炼队列：

- 屏幕访问、控件更新在 GUI 线程进行；耗时图像处理和 OCR 在后台执行。
- 每次请求记录请求编号、区域配置版本、输入版本和监测会话编号。更换区域、修改输入、暂停或关闭窗口后使旧请求失效。
- 同一时刻只执行一个 OCR 任务；高频触发最多保留一个最新请求，不积累过时截图。
- 完成时检查版本，丢弃失效结果；暂停和关闭后不再应用结果。底层推理不一定支持中断，需区分“停止接收结果”与“强行终止线程”。
- 所有校验通过后才提交。批量回填期间保护 `updating` 并阻断相关控件信号，更新选中列表、按钮、档位、启用状态及数量，结束后只调用一次 `calculate()`。
- 不通过模拟逐个点击填入，避免反复计算和自动弹出档位菜单。
- OCR 导入不可靠识别声骸身份。默认成功应用不同副词条结果时清空区域 4 锁定；结果相同则不应用、不清锁，也不能据此认定是同一只声骸，用户切换声骸后应主动清锁。
- 识别不自动扣减频整器预算。所有失败保留旧输入，并展示可操作的错误信息。

### 6. 截图、平台与配置

- macOS 验证屏幕录制权限申请、拒绝及授权后的恢复流程；打包应用需单独验证。
- 区分 Qt 逻辑坐标与截图物理像素，覆盖 Retina、混合缩放、多屏及负坐标。
- 持久化屏幕标识、区域、屏幕几何与缩放信息、透明度及用户选择的快捷键；显示器缺失或几何／缩放变化时使区域失效并提示重新框选。
- 游戏移动、分辨率或 UI 缩放变化可能导致固定区域失效；通过列表边界校验拒绝异常画面，不能宣称完全自动检测。
- 截图前隐藏框选遮罩，必要时临时隐藏本工具并等待桌面完成重绘，截图完成后恢复。实时监测不应每次隐藏窗口造成闪烁，应要求识别区与工具不重叠，重叠时暂停提示。
- 透明窗口仍可能出现在截图中；透明度滑块初始建议范围为 50%～100%，默认 100%，提供恢复入口，不实现点击穿透。
- 普通桌面截图不保证读取被遮挡、最小化或独占全屏的游戏。首版以可见的无边框／窗口模式为验证目标；黑屏或不可读画面需报告。
- 截图默认仅驻留内存，不自动写日志或保存。用户主动保存诊断截图时提示其中可能包含其他屏幕信息。

### 8. 分阶段实施

1. **样本与技术验证**：收集经过允许使用的截图，覆盖 0～5 条、13 种属性、整数／百分比、不同缩放和背景；对比引擎并验证两平台截图、模型和打包。
2. **点击识别首版**：完成固定区域框选、按钮截图、解析校验、校正确认、批量回填、状态与透明度；全局快捷键通过平台验证后接入。
3. **自动应用**：根据样本确定置信度和完整性规则，开放无歧义结果自动填入，保留强制确认选项。
4. **实时监测**：增加变化检测、稳定等待、两次结果确认、去重、单任务限流及手动编辑暂停。
5. **全屏自动定位**：在真实界面样本基础上定位面板，支持候选选择和失败时手动框选；之后再评估窗口跟随。

### 9. 验收标准与性能目标

以下是待验证的发布门槛，不是现有性能结论：

- 建立至少 100 张独立标注截图，覆盖首版宣称支持的系统、分辨率和缩放；调参与验收样本分开，记录每类覆盖情况。
- 对验收样本，完整副词条集合及数值的精确匹配率目标不低于 95%；自动应用子集不得出现错误或漏行，并报告自动应用覆盖率，不能靠全部拒绝获得“零错误”。
- 使用真实引擎测量冷启动、预热后端到端延迟和实时监测资源占用。预热后点击至可应用结果的 P95 暂定不超过 2 秒，标注测试硬件；不包含策略算法完成时间。
- 实时检测初始间隔 500～1000 ms、稳定等待约 300 ms，均以实测调整；实时端到端延迟单独测量，不能套用点击模式指标。
- 识别结果与手工输入的 `current_echo()`、评分及建议一致；一次成功批量应用只触发一次计算，重复结果不触发计算。
- 覆盖缺小数点、缺百分号、重复、非法档位、漏行、空图、动画、错误区域、遮挡和权限拒绝；均不得静默覆盖或清空。
- 测试识别期间编辑、清空、换区域、暂停及关闭窗口；旧任务不得覆盖新状态，不得更新已关闭窗口。
- OCR 初始化或执行失败时错误可见，手动录入正常；无网络打包运行通过，原有相关测试保持通过。
