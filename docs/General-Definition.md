# 总体定义与术语：《鸣潮》声骸调谐规则、数据与概率

> 用途：作为项目规则与数据配置参考。韩国官网公示了副词条类型概率公式和各副词条数值档位概率。本项目以已筛选出合适主词条的声骸作为调谐起点，不考虑主词条获取概率及刷取成本。可直接读取的数据保存在 [config/echo-stats.json](config/echo-stats.json)。

## 1. 术语

| 中文   | 英文       | 说明                                                                             |
| ------ | ---------- | -------------------------------------------------------------------------------- |
| 声骸   | Echo       | 由残象转化而来的装备，可提供主词条、小词条、副词条和声骸套装效果。               |
| 调谐   | Tuning     | 消耗调谐器解锁声骸副词条；声骸每提升 5 级开放一个调谐槽，五星声骸最多开放 5 个。 |
| 调频仪 | Modifier   | 用于调整声骸主词条的五星道具，通过“数据重构”使用。                               |
| 频整器 | Transducer | 用于修改声骸副词条的五星道具，通过“数据重构”使用。                               |

### 词条分类与统一标识

| 中文分类 | 配置字段      | 含义                                 |
| -------- | ------------- | ------------------------------------ |
| 主词条   | `main_stats`  | 按 Cost 确定候选池，调谐前已筛选确定 |
| 小词条   | `minor_stats` | 按 Cost 固定的基础词条，随等级成长   |
| 副词条   | `sub_stats`   | 通过调谐激活或通过频整器重构         |

同类词条跨分类使用相同的 `snake_case` 标识。固定值使用 `_flat`，生命/攻击/防御百分比使用 `_pct`，伤害加成使用 `_dmg_bonus`。标识不包含 `%`、空格或句点；数值展示仍可以使用 `%`。

| 中文词条     | 统一英文标识        |
| ------------ | ------------------- |
| 气动伤害加成 | `aero_dmg_bonus`    |
| 冷凝伤害加成 | `glacio_dmg_bonus`  |
| 热熔伤害加成 | `fusion_dmg_bonus`  |
| 导电伤害加成 | `electro_dmg_bonus` |
| 湮灭伤害加成 | `havoc_dmg_bonus`   |
| 衍射伤害加成 | `spectro_dmg_bonus` |
| 治疗效果加成 | `healing_bonus`     |

其余 13 种词条的统一英文标识见第 2 节。

## 4. 官方公示的副词条概率

韩国官网公示的计算规则为：

$$
P(\text{目标副词条类型及数值}) = \frac{100\%}{13 - N} \times P(\text{目标数值} \mid \text{词条类型})
$$

其中 $N$ 为已激活或锁定的副词条数量。副词条池共 13 种；可出现的副词条类型概率相同。一个目标副词条组合的概率，是该词条类型概率乘以对应数值档位概率。

### 4.1 调谐时的词条类型概率

| 已激活副词条数 | 下一条副词条中每种可选类型的概率 |
| -------------: | -------------------------------: |
|              0 |                  7.6923%（1/13） |
|              1 |                  8.3333%（1/12） |
|              2 |                  9.0909%（1/11） |
|              3 |                 10.0000%（1/10） |
|              4 |                  11.1111%（1/9） |

已激活的副词条不会重复出现；主词条、小词条不计入副词条重复排除。

### 4.3 频整器重构

官网说明：使用频整器重构时，已锁定的副词条不会重复出现；本次被重构的副词条类型仍可能再次出现。可重构词条类型的概率随锁定数量变化：

| 锁定副词条数 | 重构副词条数 | 每种可选类型的概率 |
| -----------: | -----------: | -----------------: |
|            1 |            4 |    8.3333%（1/12） |
|            2 |            3 |    9.0909%（1/11） |
|            3 |            2 |   10.0000%（1/10） |
|            4 |            1 |    11.1111%（1/9） |

重构目标词条的类型概率还需乘以第 4.2 节对应的数值档位概率。频整器仅能用于已完成调谐的五星声骸。策略计算仅针对副词条调谐及重构，不包含主词条抽取。

上表是公示的单个副词条类型概率，不是“本次重构的任意一个槽位出现目标词条”的整体概率。若要计算多个槽位的联合结果，需结合不重复约束建模，不能简单将各槽位视为独立事件。

### 4.4 计算示例

- 尚未激活副词条时，首条出现 10.5% 暴击率的概率为 $\frac{1}{13}\times 3\%\approx 0.230769\%$。
- 已激活 4 条且尚未出现暴击率时，第 5 条出现 10.5% 暴击率的概率为 $\frac{1}{9}\times 3\%\approx 0.333333\%$；若暴击率已激活，该事件概率为 0。
- 锁定 4 条且没有锁定暴击率时，重构剩下 1 条为 10.5% 暴击率的概率同为 $\frac{1}{9}\times 3\%\approx 0.333333\%$；被替换的原词条即使是暴击率，也不因此被排除。

## 5. 配置结构与数据维护

配置文件：[config/echo-stats.json](config/echo-stats.json)。仅维护一个 JSON 文件，供后续不同语言的程序读取。

| 配置字段                         | 内容                                                        |
| -------------------------------- | ----------------------------------------------------------- |
| `stat_definitions`               | 20 种词条的统一标识、中文名与数值单位                       |
| `main_stats.max_values_by_cost`  | 各 Cost 全部主词条候选及五星 +25 满级值                     |
| `minor_stats.max_values_by_cost` | 各 Cost 小词条及五星 +25 满级值                             |
| `sub_stats.tiers`                | 13 种副词条的升序档位数组及概率分布引用                     |
| `probability_distributions`      | 官方公示的 4 组档位概率；共享分布避免重复维护               |
| `activation.steps`               | 激活第 1–5 条时的解锁等级、候选数、精确类型概率分数与公示值 |
| `reconstruction.cases`           | 锁定 1–4 条时的重构类型概率及规则                           |
| `sources`                        | 官方副词条数据与社区主/小词条数据的来源区别                 |

- 百分比词条用**百分点**保存，例如 `atk_pct` 的 `18.0` 表示 18%，用于倍率计算时除以 100；固定值不转换。
- 档位 `values[i]` 与引用的 `published_probability_pct[i]` 一一对应。后者保存官网显示百分比，例如 `3.0` 表示 3%；实际抽样按各组总和归一化为 0–1 概率。
- 类型概率用 `numerator / denominator` 保存精确分数，例如 `1 / 13`；`published_type_probability_pct` 仅用于展示官方四位小数。
- 候选主词条以每个 Cost 的键集合为准，不额外保存获取概率；小词条不参与随机抽取。

- 将词条定义、数值范围、Cost 候选池、概率模型拆分存储，避免把估算写死在逻辑中。
- 每条数据记录来源、采集日期、游戏版本、样本量及可信度。
- 概率配置应注明来源状态。副词条类型及档位概率为 `official`；主词条、小词条满级值来源为 `community`。主词条作为已筛选确定的输入，不配置抽取概率。模拟结果应注明适用公示、模型约束及是否含项目假设。
- 若采集到与当前范围不符的有效样本，先核实声骸稀有度、等级、版本和显示精度，再更新数据。
