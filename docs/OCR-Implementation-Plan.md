# OCR 首版代码实施方案

> 状态：待实施。本文记录已确认的产品边界、代码拆分、实现顺序和验收要求，不代表 OCR、截图或打包能力已验证。
>
> 关联：[总体技术方案](OCR-Plan.md)。两份文档范围不一致时，首版以本文为准。

## 1. 已确认范围

| 项目 | 首版要求 |
| --- | --- |
| 系统 | Windows 11 x64、macOS Apple Silicon；不新增 Linux 支持承诺 |
| 游戏界面 | 简体中文、开孔过程的一个指定页面；具体页面与布局待真实截图确认 |
| 识别对象 | 已开 1～4 条副词条的名称与档位；不识别主词条、Cost、五条开满或洗炼结果 |
| 触发方式 | 首次框选并记住固定区域，之后点击按钮截图识别 |
| 应用方式 | 每次预览、允许校正、明确确认后整组替换；失败或取消保留原输入 |
| 辅助功能 | 窗口透明度 50%～100%、置顶开关、框选前自动最小化本窗口 |
| Windows 发行 | 同一版本同时发布整合 EXE、EXE＋依赖目录两种形式 |
| macOS 发行 | OCR 运行库与模型内置于 `.app` |
| 离线要求 | 三种发行形式均不依赖运行时下载、系统 Python 或独立 OCR 工具 |
| 暂不实现 | 实时监测、自动应用、全局快捷键、全屏自动定位、窗口跟随、点击穿透 |

OCR 仅辅助区域 2 录入，不管理区域 4 锁定、洗炼预算或洗炼结果。更新后仍调用现有计算入口；区域 4 会依据已有“五条开满才能使用”的规则刷新，不绕开或修改这一规则。

首次识别前允许区域 2 为空。OCR 检查的是截图内容，不以当前 GUI 已选数量推断截图已开数量。零条及五条截图不应用，不截取其中四条冒充合法结果；第五条开出后由用户手动录入。

## 2. 当前代码基线与修改原则

- [EchoWindow](../src/echo_gui.py) 的 `_stats_panel()` 构造区域 2；`selected_sub_stats`、`sub_stat_buttons`、`sub_tier_inputs` 分别维护选中项和控件。
- `current_echo()` 已输出名称与数值列表；`calculate()` 统一刷新评分并调度策略与洗炼。保持输入契约及计算算法不变。
- 逐条调用 `_toggle_sub_stat()` 会触发计算，并可能弹出档位菜单，因此新增原子批量入口，不模拟鼠标点击。
- 现有策略和洗炼使用独立串行 `QThreadPool`、输入快照与版本号。OCR 复用设计模式，不复用其线程池或版本号。
- [词条配置](../config/echo-stats.json) 是合法类型和数值档位的唯一来源；不得降低 [评分器](../src/echo_score.py) 的校验要求来迁就识别错误。
- [打包配置](../WWEcho.spec) 目前 Windows 使用单文件，macOS 使用 `COLLECT` 与 `BUNDLE`；新增 Windows 目录发行分支，避免复制整套打包配置。
- [GUI 测试](../tests/test_echo_gui.py) 已使用离屏 Qt、临时目录和可控后台任务；OCR 测试沿用这些方式。

只调整 OCR 直接相关界面、状态、依赖、打包和说明，不重构评分／策略算法，也不改权重方案存储行为。

## 3. 建议文件与职责

以下新增文件名和接口是实施约定，不是已有实现。

| 文件 | 职责 |
| --- | --- |
| `src/echo_capture.py` | 屏幕标识、区域与快照类型；框选遮罩、截图和坐标转换 |
| `src/echo_ocr.py` | 类型化 OCR 数据、本地引擎适配、名称与数值解析、合法性校验；解析部分不依赖 Qt 控件 |
| `src/echo_ocr_gui.py` | 识别控制器、独立后台任务、预览校正对话框和识别设置读写 |
| [src/echo_gui.py](../src/echo_gui.py) | 入口、透明度与置顶、版本通知、批量应用及关闭协调 |
| `tests/test_echo_capture.py` | 坐标转换、区域有效性及截图失败测试 |
| `tests/test_echo_ocr.py` | OCR 文本解析与配置校验，不要求安装真实引擎 |
| `tests/test_echo_ocr_gui.py` | 假引擎／假截图驱动的状态机、确认、取消与过期测试 |
| `tests/fixtures/ocr/` | 经允许纳入仓库的样本及标注；真实图片授权未确认前不提交 |

不提前构建引擎插件系统或实时监测框架。通过一个截图入口、一个引擎适配入口和一个应用入口保留后续扩展能力。

## 4. 数据与接口约定

采用明确类型的数据类或等价结构，不以多层无约束字典串联识别链路。保持项目支持的 Python 语法范围，具体引擎兼容性未确认前不擅自提高最低版本。

| 类型 | 主要字段与约束 |
| --- | --- |
| `CaptureRegion` | 屏幕标识、屏幕几何、缩放、屏幕内逻辑坐标矩形；仅允许单屏内非空区域 |
| `CaptureSnapshot` | 独立图像快照、实际像素尺寸、截图时间、区域版本 |
| `OcrToken` | 原始文字、截图像素坐标框、引擎置信度 |
| `ParsedSubStat` | 规范 `stat_id`、配置中的规范数值、原始行、问题标记；未确定字段保持显式未确定 |
| `OcrResult` | 行结果、未匹配文本、完整性状态、阻断问题及可校正问题；不将无结果表示成成功空列表 |
| `OcrRequest` | 请求编号、输入版本、区域版本和独立图像快照 |
| `OcrOutcome` | 请求标识及结果，或明确错误类别与信息；成功／失败不可混用 |

建议接口：

- `capture_region(region) -> CaptureSnapshot`：GUI 线程访问屏幕，失败报告具体原因。
- `recognize(image_array) -> list[OcrToken]`：后台调用本地引擎；引擎专有返回值在此转换。
- `parse_sub_stats(tokens, stats) -> OcrResult`：无 GUI、无模型依赖的解析函数。
- `validate_selection(entries, stats)`：确认前验证 1～4 条、唯一类型、配置档位；返回规范化结果或明确错误。
- `apply_ocr_sub_stats(entries)`：主窗口唯一批量应用入口，再次验证后提交。

数值沿用 `current_echo()` 的百分点单位，例如 `10.5` 表示 `10.5%`。档位索引由配置推导，不在 OCR 内另建数值表。确认后的每项转换为 `{"name": stat_id, "value": value}`。

## 5. 截图、框选与窗口行为

### 5.1 首次框选

1. 保存主窗口正常／最大化状态、几何和置顶状态，最小化本窗口。
2. 通过 Qt 事件调度等待桌面重绘，不在 GUI 线程调用阻塞式休眠。
3. 获取屏幕画面，显示截图框选遮罩。鼠标按下时确定目标屏幕；首版拒绝跨屏选区。
4. 拖动选择完整副词条列表，包含已开行和用于判定列表边界的未解锁部分；具体框选提示待样本确认。
5. 确认后验证区域并保存；Esc、空选区、截图失败均不覆盖原有效配置。
6. 销毁遮罩，在成功、取消及异常路径恢复原窗口状态和置顶设置。

框选时使用冻结画面，避免遮罩进入自身截图。以实际屏幕返回图像验证坐标换算，不能假定逻辑坐标与像素坐标相等。

### 5.2 点击识别

- 先验证目标屏幕存在、几何与缩放仍匹配、选区未越界；不将失效区域静默迁移到主屏。
- 若工具与选区重叠，临时最小化本窗口后截图，并恢复；若无重叠则直接截图。透明窗口仍视为遮挡。
- 截图限定在选区，尽早释放无关全屏图像；截图与 OCR 文字默认不落盘、不上传。
- 将 `QPixmap` 在 GUI 线程转换成有独立所有权的图像数据，工作线程只处理图像快照／数组，不操作屏幕或控件。
- 截图权限拒绝、返回空图、尺寸异常等给出具体提示。不能可靠区分黑色游戏场景与捕获故障时，提示画面不可识别，而不是武断判断权限问题。

### 5.3 平台与窗口设置

- Windows 11 验证 100%／150%／200% 缩放、混合缩放多屏、负坐标、置顶切换后的窗口恢复。
- macOS 验证 Retina、屏幕录制权限拒绝与授权恢复，以及冻结应用的权限行为。
- 普通截屏只承诺可见窗口／无边框游戏画面；不承诺后台、最小化、被其他应用遮挡及独占全屏。
- 透明度默认 100%，取值 50%～100%；置顶默认关闭，两项均可恢复默认并持久化。
- `WindowStaysOnTopHint` 切换可能影响窗口显示，必须保存并恢复几何、窗口状态，不能导致窗口消失或重复触发框选。

## 6. OCR 解析与预览校正

### 6.1 引擎验证

优先验证 RapidOCR + ONNX Runtime 的 CPU 方案。只有依赖兼容、中文小字／小数点效果和三种发行产物均可接受，才固化版本；不满足时再比较替代引擎，不同时集成多个后端。

模型路径显式指向随包资源；首次点击才加载模型，串行工作队列中复用实例。依赖缺失或模型损坏只禁用该次 OCR，显示错误，不阻断应用启动和手动录入。

验证项目现有 Python、NumPy 和 Qt 约束。若必须提高最低 Python 版本或放宽依赖边界，先单独提出兼容性决策，不在本方案中默认授权。

### 6.2 解析步骤

1. 按位置组合文字行，配对词条名称与数值，保留所有未匹配项。
2. 统一空白、全角数字和符号；名称通过配置名及经截图验证的显式别名映射。
3. 区分固定数值与百分比，不因数值接近某档位就推断类型。
4. 对照该词条的配置数值匹配档位，成功后使用配置中的规范数值。
5. 对重复类型、超出范围、单位不明、漏行、非法档位分别给出问题。
6. 列表边界、行数量和未解锁槽位检测由真实样本确定。在此之前完整性只能标记为“待人工核对”，不得宣称完整。

禁止静默修复小数点、强取最近档位、忽略多余行或截断五条结果。截图确认为零条／五条或非目标页面时阻断应用；疑似漏行必须让用户在原图中核对。

### 6.3 确认对话框

- 同时显示原始区域截图、原始识别文字、解析后的词条与档位、问题提示。
- 词条与档位使用合法候选下拉框；允许修正漏识别项，但最终必须为 1～4 个不重复类型。
- 无任何候选时提示识别失败并要求重新截图，不把空结果作为可应用状态。
- “确认替换”前校验全部字段，要求用户核对画面实际为已开 1～4 条；不允许通过删除第五行绕过范围限制。
- 未解决的结构性阻断问题禁用确认。取消不改变 GUI 输入、评分、权重或预算。
- 提示沿用当前 Cost 和主词条；应用范围仅为副词条，不推断是否同一只声骸。

## 7. 状态机、并发与批量应用

### 7.1 首版状态机

```text
未配置 → 框选 → 就绪
就绪 → 截图 → 识别 → 待确认 → 应用 → 就绪
                 ↘ 失败 → 就绪／未配置
待确认 → 取消 → 就绪
任意状态 → 关闭中（拒绝新请求）
```

首版每次只允许一个识别请求；截图／识别／确认期间禁用重复识别入口，不建设任务积压队列。手动修改区域 2 仍可用，但应使在途请求失效；模态确认对话框不允许背后修改输入。

### 7.2 版本与线程

- 独立 OCR 控制器拥有单线程 `QThreadPool`、当前任务引用和引擎实例；任务不持有主窗口。
- 手动增删词条、修改档位、清空、切换 Cost／主词条更新 OCR 输入版本；框选更新区域版本。
- 接收后台结果和点击确认时都核对请求、输入、区域版本及关闭状态；过期则提示重新识别，不覆盖新输入。
- 区分任务异常、用户取消和过期结果。预期错误具体处理；后台边界可兜住异常，但必须通过结果信号报告类型和信息，不返回成功空列表。
- 用户确认关闭且权重保存流程通过后，拒绝新请求、使 OCR 失效、关闭预览和遮罩、释放图像。
- 不强杀推理线程。若仍有 OCR 工作，使用事件驱动的关闭等待，显示“正在结束识别”，完成后再回收 OCR 线程池；不能让工作线程访问已销毁控件。底层推理超时／关闭行为属于引擎验证门槛。

### 7.3 原子回填

1. 在任何 GUI 修改前验证所有条目、版本和目标档位是否存在。
2. 比较规范化后的类型／数值集合；相同则报告“与当前输入一致”，不重算、不重排。
3. 保存 `updating` 和控件信号状态，用保护块临时抑制自动计算和下拉弹出。
4. 一次性替换选中列表、按钮、下拉档位、启用状态及数量；取消未出现在结果中的旧选择，不能只追加新词条。
5. 无论成功或异常都恢复信号与 `updating`；预期校验失败必须在提交前结束，异常不得留下半更新状态。
6. 成功提交后更新输入版本，只调用一次 `calculate()`。不直接调用洗炼控制、清锁或预算接口。

## 8. 配置与资源路径

- 新增独立 `ocr-settings.json`，保存 schema 版本、区域、屏幕信息、透明度和置顶；不保存图片、OCR 原文或声骸数据。
- 路径通过现有 `weight_presets_path().parent` 取得，延续源码根目录／EXE 旁／`.app` 旁的可写目录约定；不与权重内容合并。
- 首次不存在使用明确默认值。格式损坏／不支持的版本需提示用户重新配置；不得静默覆盖损坏文件。写入使用原子替换并报告失败，当前会话设置可继续使用但标记未保存。
- 测试将设置路径指向临时目录，不能读写真实用户配置。
- OCR 模型使用随包只读资源路径，与可写设置路径分离；禁止把配置写入单文件 EXE 的临时解包目录或 macOS 包内部。

## 9. 三种发行产物

### 9.1 Windows 11 x64：两种形式必须同时交付

| 形式 | 建议产物布局 | 行为 |
| --- | --- | --- |
| 整合 EXE | `dist/windows-onefile/WWEcho声骸工作台.exe` | 运行库和模型打入 EXE，PyInstaller 在运行时解包；用户无需另配依赖目录 |
| EXE＋依赖目录 | `dist/windows-onedir/WWEcho声骸工作台/`，包含 EXE 与 `_internal/` 等资源 | 整个目录压缩分发，用户完整解压后运行，不可只复制 EXE |

“单文件”指运行所需组件被整合，不表示运行时零解包，也不禁止在 EXE 旁生成权重和识别设置。两种形式使用同一代码、模型、依赖版本与功能，分别验证，不以其中一种成功代替另一种。

### 9.2 打包入口

- 修改 [Windows 构建脚本](../build-windows.bat)，计划支持 `all`、`onefile`、`onedir`；无参数默认 `all`，保留一键构建体验。
- 使用显式构建模式传给 [WWEcho.spec](../WWEcho.spec)，例如由脚本设置 `WWECHO_BUILD_MODE`；校验允许值，不使用 `eval` 或依赖 PyInstaller 对 spec 模式下无效的 `--onefile/--onedir` 开关。
- Windows 单文件保留 `EXE` 内嵌二进制和数据；目录模式使用 `exclude_binaries=True` 与 `COLLECT`。
- 两种构建使用独立 `--distpath` 和 `--workpath`，避免清理、文件名和缓存相互覆盖；任意一种失败都报告整体未完成，不只打印一个成功路径。
- [macOS 构建脚本](../build-macos.sh) 仍产出内置依赖的 `.app`，保留现有输出路径；验证构建解释器及运行库均为 Apple Silicon 兼容架构。
- 收集引擎所需动态库、模型、字典和必要导入；只添加实测需要的 hook／hidden import，不盲目收集整套开发依赖。
- 核对运行库与模型的许可证、来源和分发要求；使用有版本记录的模型，禁止启动时隐式下载。随包提供要求的第三方许可信息。

### 9.3 发行验证

在无 Python、无 OCR 系统安装、断网环境逐一验证三个产物：

1. 手动录入、权重保存、OCR 模型加载和一次完整识别确认流程。
2. 中文／空格路径、非项目当前工作目录、首次启动与再次启动。
3. 模型和动态库真实从发行资源加载，而非开发机缓存或项目目录。
4. 配置能跨重启保存，升级可保留；不可写目录明确报错，不偷偷写到临时目录。
5. Windows 单文件冷启动与临时解包成本，目录版完整解压后运行；两者 OCR 结果相同。
6. macOS 实际 `.app` 权限、模型加载和窗口行为；无签名／公证时如实说明，不把本地打包成功当作发行认证。

## 10. 实施顺序与完成条件

| 步骤 | 工作 | 完成条件／前置 |
| --- | --- | --- |
| A. 样本与兼容性验证 | 确认指定页面，验证截图、CPU 引擎、依赖和模型分发 | 真实样本待用户提供；选型结论与三种构建风险明确 |
| B. 数据与解析 | 实现结果类型、名称映射、档位校验和解析单测 | 不加载模型即可运行；真实别名／布局依赖 A，合成数据契约可先做 |
| C. 截图与设置 | 框选、坐标转换、窗口恢复、设置读写、透明度和置顶 | 双平台基础行为验证；与 B 可独立进行 |
| D. 点击识别链路 | 后台任务、状态机、预览校正、取消与错误显示 | 依赖 B、C；假引擎和真实引擎都跑通 |
| E. 批量回填 | 主窗口版本通知、唯一应用入口、关闭协调 | 依赖 D；一次应用一次计算，旧结果不覆盖新状态 |
| F. 发行打包 | 依赖固化、模型收集、Windows 双构建、macOS 构建 | 依赖 A、E；三个产物断网可用 |
| G. 回归与文档 | 真实样本回归、平台手测、使用说明 | 依赖 F；未满足门槛的项目明确列出，不标记发布完成 |

本轮只编写方案，不执行 A～G，不安装依赖、不下载模型、不构建程序。

## 11. 测试与验收清单

### 自动化

- 解析：13 种合法类型及其档位、1～4 行、整数／百分比、文字数值分离、全角字符、误字、缺小数点／百分号、重复、非法数值、漏行、零条／五条拒绝。
- 截图：矩形归一化、缩放、多屏负坐标、跨屏拒绝、屏幕消失、空图、尺寸变化、取消后恢复原区域和窗口。
- GUI：无配置、识别中禁止重复触发、取消与失败不修改输入、校正合法性、旧选择被完整替换、无意外档位弹窗。
- 并发：识别期间编辑／清空／改区域、确认前版本变化、关闭中任务返回、权重关闭确认取消；不丢失正常窗口状态。
- 下游：相同结果零次计算，不同合法结果一次计算；`current_echo()` 与等价手动录入一致，评分和开孔建议保持一致；OCR 不开启洗炼、不修改预算和锁定业务逻辑。
- 配置：缺失、损坏、未知版本、不可写及原子写入失败，均有可见反馈。
- 用假引擎控制完成时机和异常；离屏测试不调用真实屏幕权限、不依赖模型下载。

实现时优先运行 `python -m unittest discover -s tests -p 'test_echo_ocr*.py'` 与截图测试，再覆盖现有 GUI／评分／策略相关回归；发行前运行现有完整测试集。没有新增 pytest 或独立测试框架的需求。

### 真实样本与手测

- 用户将提供真实开孔过程截图；先验证指定页面和 1→2→3→4 条变化，并包含零条、五条和非目标画面作为拒绝样本。
- 标注名称、数值、实际已开数量、区域位置和显示条件。样本不含不必要个人信息；是否允许提交仓库需另行确认。
- 延续总体方案的至少 100 张独立标注验收样本、完整集合精确匹配率不低于 95%作为待验证目标；调参与验收集分开，真实样本不足时明确记录，不用复制样本凑数。
- 精确匹配率统计用户校正前的完整结果；单独报告拒绝率和人工修正率。首版不实现自动应用，因此不把“自动应用正确率”作为首版指标。
- 预热后点击至预览可见 P95 暂定不超过 2 秒，不包含用户确认时间与策略计算；单列模型冷加载、单文件解包、CPU 和内存峰值，记录硬件与图片尺寸。
- Win11 两种发行及 macOS 均需实机验收权限、缩放、框选／取消恢复、置顶、透明度和窗口重叠截图。没有对应环境时列为未验证，不能仅凭单测通过宣称支持。

## 12. 待样本确定与后续边界

当前未验证：目标页面布局、未解锁槽位特征、OCR 行配对参数、名称别名、预处理方式、置信度阈值、引擎版本和模型资源清单。拿到样本后补齐，不提前硬编码坐标或声称可以判断所有漏行。

后续实时监测可以复用截图、解析、请求版本和回填入口，但必须另行实现变化检测、稳定判断、暂停与自动应用安全门槛。全屏定位需要独立的面板定位证据；全局快捷键需要独立平台注册与冲突处理。首版不为这些功能添加隐藏开关或未验收的半成品逻辑。
