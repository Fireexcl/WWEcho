# 洗炼／洗词条算法：频整器概率、收益与消耗

实现见 [单次计算](../src/echo_reconstruction.py)、[动态预算计算](../src/echo_reconstruction_budget.py) 与 [窗口](../src/echo_gui.py)。仅用于**已开满五条副词条**的五星声骸；锁定 1～4 条时，每次分别消耗 1、1、2、3 枚频整器，其余词条的属性、档位全部重新随机。材料口径来自本功能需求，不把它包装成新增核实的官方成本公示。

## 1. 输入与操作

1. 在区域 2 选择五种副词条及档位。区域 4 的五个按钮同步显示它们，点击表示同时锁定属性和当前档位，最多锁四条。
2. 当前锁法的五个高亮结果框依次显示单次升分概率、成功时平均Δ分、升分期望消耗、单次期望Δ分和单次消耗；表格另列单位收益，不需要设置区域 3 的目标。
3. “单次”页列出全部 30 种锁法，点击一行可套用。按锁数分组，同组按单次期望变化降序显示。期望Δ分与成功时平均Δ分使用相同的字体规则：有效数值加粗，正值为绿色、负值为红色，零值与无定义值保持中性。
4. 预算默认三枚，支持 0～6 枚。“同预算”页比较动态择优和所有有序消耗拆分；三枚为 `1+1+1`、`1+2`、`2+1`、`3`。每次可接受或拒绝候选，再按实际保留状态换锁；各执行方案完整用完预算，“不投入”仅作独立对照，不混入方案均值。
5. 修改词条、档位、权重或预算会使旧结果立即失效，独立后台计算最新输入；选锁直接复用结果，预算变化复用单次分析和条件期望缓存，不等待区域 3 的激活策略。大预算或大量非零权重首次计算较久。
6. 点击拆分方案只套用首步锁法。实际重构后，将实际保留的五条属性与档位录入区域 2，预算扣除本次消耗，再获取下一步建议。拒绝候选则原词条不变，但频整器仍消耗；不能事先给随机结果指定固定后续锁法。

预算工具栏右侧的“清空锁定”可一次取消全部锁定，样式与区域 2 的“清空勾选”一致。工具栏与结果区之间使用分隔线，不再显示“频整器已更新”成功文本；未开满、等待/计算和错误提示仍保留。

结果区仅保留五个单次指标框与“单次”“同预算”结果表，不再显示当前锁法或动态方案的文字摘要框；等待与错误提示由状态行显示，不影响查看已有的单次结果。

## 2. 复用配置，不新增参数文件

[属性配置](../config/echo-stats.json) 已包含：

- `reconstruction`：必须开满五条、锁数与重构数、排除锁定类型、允许原未锁类型再次出现。
- `sub_stats`：13 种类型、不重复约束和合法档位。
- `probability_distributions`：官方公示的非均匀档位概率，计算时归一化。

频整器消耗按规则 `1→1、2→1、3→2、4→3` 计算。预算是本次界面输入，不是持久化规则。未改动用户权重，也未把 [普通激活成本](../config/activation-costs.json) 当作频整器成本。

## 3. 单次概率与收益

当前副词条集合为 $E$，锁定集合为 $L$，$m=|L|$，重构 $r=5-m$ 条。候选类型池 $U$ 为全部副词条类型排除 $L$，大小 $13-m$；**不排除原来未锁定的类型**，也不排除同名主词条、小词条。

从 $U$ 中等概率不放回选择 $r$ 种类型。给定类型后，按各类型归一化公示概率独立选择档位；跨档位和跨次独立是计算模型约定，未额外宣称存在官方联合概率公示。

设 $B$ 为选中的类型子集，$q_{j,k}$ 为类型 $j$ 的档位概率：

$$
P(B,\mathbf{k}\mid L)=\frac{1}{\binom{13-m}{5-m}}\prod_{j\in B}q_{j,k_j}
$$

令 $g_{j,k}$ 为该档位按当前权重计算的贡献，当前未锁定贡献和为 $t$：

$$
\Delta=\sum_{j\in B}g_{j,k_j}-t
$$

主词条、小词条、锁定词条不会变化，比较新旧总分时抵消。分数对齐分母仍与全局评分器一致，不因锁数改变。

| 指标          | 定义                           | 含义                                                                 |
| ------------- | ------------------------------ | -------------------------------------------------------------------- |
| 正提升概率    | $p=P(\Delta>0)$                | 平分不是成功，与目标是否达成无关                                     |
| 期望Δ分       | $\mu=\mathbb E[\Delta]$        | 包含降分风险，可能为负                                               |
| 正收益期望    | $A=\mathbb E[\max(\Delta,0)]$  | 只计算正向部分，不代表可免费拒绝失败                                 |
| 降分期望      | $D=\mathbb E[\max(-\Delta,0)]$ | $\mu=A-D$，内部用于稳定计算                                          |
| 成功时平均Δ分 | $A/p$                          | 仅在正提升条件下的平均收益；$p=0$ 时无定义                           |
| 正收益 / 枚   | $A/c_m$                        | 单次毛收益效率，不能代替含降分风险的净期望                           |
| 升分期望消耗  | $c_m/p$                        | 无限预算、固定锁法、首次超过原始评分即停的期望消耗；$p=0$ 时不可获得 |

其中 $c_m$ 为锁定 $m$ 条时的单次消耗，按 $c_1=1,c_2=1,c_3=2,c_4=3$。

### 算法与精度

五条中锁 1～4 条，共有 $5+10+10+5=30$ 种锁法。每种锁法最多枚举 $\binom{12}{4}=495$ 个类型子集。

每个子集拆成两半，每半至多两种类型、最多 64 个档位组合。合并相同贡献，并缓存有序分布、前后缀概率和相对局部基点的一阶矩；对每个左半结果二分右半的严格尾区间，直接累计概率与正负收益，避免展开所有四条档位笛卡尔积。

- 词条数值、权重的十进制乘积转为有理数，再统一为整数贡献，**严格比较整数新旧差**。不使用展示舍入值，也没有分数网格量化。
- 净期望从有理数一阶矩直接求差；收益先计算整数差再对齐，用局部基点累计尾矩，避免很大的相近分数相减吞掉细小提升。
- 概率和正负收益最终以双精度浮点累计。称为“对离散模型求和”，不表示无限数值精度，更不表示恢复了官方显示值之前的原始概率。
- 公示四位小数存在圆整，仍按每组总和归一化，不反推所谓官方整数权重。

## 4. 同预算动态换锁与最终方案收益

### 保留或拒绝候选，实际执行洗练

**每次洗练先实际支付频整器，看到候选后选择保留或不保留；拒绝时沿用原词条，本次频整器仍然扣除。** 后续根据实际保留的五条属性、档位和剩余预算重新选择锁法及锁数。接受候选后可以锁住新词条；拒绝后仍在原状态上决策。

**同预算表比较完整执行的方案，不把“还没洗就放弃”的零收益、零消耗分支混入期望。** `1+1+1` 就实际洗三次、消耗三枚；`1+2` 与 `2+1` 各洗两次、消耗三枚；`3` 洗一次、消耗三枚。可以拒绝每一次的候选，但不能把拒绝候选当成未执行洗练。不投入只是一条单独基线。

设 $s$ 为实际保留的完整状态，$s'$ 为本次候选，$S(s)$ 为评分，$V_b(s)$ 为实际使用剩余 $b$ 枚后的最优最终评分期望：

$$
V_0(s)=S(s),\qquad
V_b(s)=\max_{L:\,c_{|L|}\le b}
\mathbb E\left[\max\left\{V_{b-c_{|L|}}(s),\ V_{b-c_{|L|}}(s')\right\}\mid s,L\right].
$$

内层两个分支分别为拒绝候选并保留旧状态、接受候选；两者都已支付本次消耗。比较的是剩余预算下的最终价值，不是强制替换，也不是只比较本次表面分数。主词条和小词条不变。

固定花费后缀同样递推，只把本次可选花费限制为该序列的首项。相同最终价值选择较少洗练次数；新旧分支仍平分时保留旧状态。最后一次洗练的收益为 $\mathbb E[\max(S(s')-S(s),0)]$，拒绝导致的零提升属于**已实际洗过**的结果，应正常计入。这里不改动“单次”页面已有候选原始期望、正收益等指标。

### 三枚预算比较哪些方案

| 行       | 允许的花费方式                   | 后续锁法                           |
| -------- | -------------------------------- | ---------------------------------- |
| 不投入   | 0 枚，独立基线                   | 不与任何执行方案混算               |
| 动态择优 | 实际用完三枚，按结果调整花费路径 | 每次接受/拒绝后重新选锁            |
| 1+1+1    | 依次各花 1 枚，实际洗三次        | 每步可锁 1 或 2 条，按保留状态择优 |
| 1+2      | 先花 1 枚，再花 2 枚，实际洗两次 | 首步锁 1 或 2 条，后续重新选 3 条  |
| 2+1      | 先花 2 枚，再花 1 枚，实际洗两次 | 首步锁 3 条，后续重新选 1 或 2 条  |
| 3        | 一次花 3 枚，实际洗一次          | 首步锁 4 条，候选不满意可拒绝      |

固定拆分只限定每次花费，不固定词条；不能跳过前项直接执行后项。`1+2` 与 `2+1` 不等价。动态择优可以在看到不同结果后采用不同后续花费，故一般不能仅取四条事先固定拆分的最大值来代替它。

### 表格列的含义

- **首步锁定 / 消耗**：现在可执行的首步动作；后续要等实际结果再选，点击行只套用首步。
- **最终期望分数**：$\mathbb E[S_{\mathrm{最终保留}}]$。
- **最终期望Δ分**：$\mathbb E[S_{\mathrm{最终保留}}-S_{\mathrm{开始}}]$。包括每次接受/拒绝决策；不掺入未洗就放弃的分支，也不是只对升分成功的样本取平均。
- **期望实际消耗 / 期望次数**：实际用完预算的材料和执行次数。固定拆分的次数就是拆分长度；动态择优的次数可能随花费路径变化，但拒绝候选也照算一次。
- **平均升分 / 枚**：最终期望Δ分除以期望实际消耗；不投入时无定义。推荐先最大化最终分数期望，不按该比值单独优化；未把材料换算成分数效用。

旧“下次边际”针对固定锁法多洗一次，已从动态预算表移除。若要研究额外一枚的动态价值，其定义应为 $V_{b+1}(s)-V_b(s)$，需要比较两个预算下重新优化后的策略，不能沿用旧模型的概率幂公式。

### 新旧状态比较算法、缓存与数值口径

旧算法只缓存给定锁定集合下的新结果平均后续价值，丢失了当前状态可保留这一比较基准，不能用于可拒绝候选的机制。当前保存每个后缀政策在完整离散状态上的 $G_b(s)=V_b(s)-S(s)$ 及次数，动作必须对新旧两个后缀价值逐结果取较优：

$$
G_b(s)=\max_{L:\,c_{|L|}\le b}\left(
G_{b-c_{|L|}}(s)+\mathbb E\left[\max\left\{
S(s')-S(s)+G_{b-c_{|L|}}(s')-G_{b-c_{|L|}}(s),\ 0\right\}\mid s,L\right]\right).
$$

- 按锁定类型和档位分组，将候选后续价值排序，缓存概率累计量及相邻价值差尾矩。对原状态的后续价值查找可接受尾区间，累计收益及实际次数；拒绝分支使用原状态后续政策。
- 类型子集仍等概率不放回，档位按归一化概率；锁定档位是观测条件，不能再乘其抽取概率。合法零概率档位仍可作为原状态保留，不能因概率为零而丢失拒绝分支。
- 同类型同贡献档位合并概率以减小计算规模，仍保留类型身份。不能只根据总分合并不同词条状态，否则会丢失下一步的可锁信息。
- 全动态与固定花费后缀构成共享的决策图；同一后缀的条件期望表复用，预算和当前声骸变化仍可复用。权重或概率变化则新建计算器。
- 各执行方案的材料固定为完整预算，平分时只比较较少次数，不加入停止动作；新旧接受选择和次数来自同一后缀政策。
- 候选与原状态的锁定贡献先抵消，再用整数局部基准差转为 `longdouble`；尾矩使用相邻价值差降低消去误差。超出 int64 范围走有理数转换。仍是有限精度，不宣称数学无限精确。
- 没有分数网格或蒙特卡洛。为避免内存失控，多步状态上限 100 万、后缀缓存 192 MiB，超过则报告动态结果不可用，不截断、不抽样，**单次结果仍正常显示**。预算范围 0～6，默认 3；较多非零权重或较大预算可能超限。
- 后台串行计算、取消检查、版本拒旧；只发布完整后缀表，取消后的半成品不能被复用。

API：`ReconstructionPlanner.compare_dynamic_budget(echo, budget)` 返回动态表格 `rows`、完整执行预算的 `recommendation`、以及 30 种实际执行首步后接动态策略的 `first_plans`。首步必须支付，但候选可拒绝，故动态收益非负；超过预算时 `dynamic_budget=None`。旧 `evaluate_budget` / `compare_budget` 和单次分析均不在本次修改范围，**动态界面不使用旧固定锁法 API**。
