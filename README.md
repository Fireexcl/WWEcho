# 声骸评分原型

评分核心使用 Python 标准库；策略计算使用 NumPy，独立窗口使用 PySide6，依赖见 [requirements.txt](requirements.txt)。当前代码兼容 Python 3.9+；新环境建议使用 Python 3.12。计算入口在 [src/echo_score.py](src/echo_score.py)，窗口入口在 [src/echo_gui.py](src/echo_gui.py)。

## 独立窗口 GUI

Windows 用户可双击 [WWEcho.exe](dist/WWEcho.exe) 直接运行，无需在目标电脑安装 Python 或项目依赖。该单文件程序包含 GUI 依赖和默认配置；首次打开可能需要几秒解压。要自行构建或更新 EXE，在 Windows 上双击 [build-windows.bat](build-windows.bat)，脚本会安装构建依赖并生成 `dist/WWEcho.exe`；构建机需要 Python 3.9+ 和网络连接。也可在开发环境双击 [run.bat](run.bat) 启动源码版本。macOS/Linux 或 WSL 用户先在项目虚拟环境中安装 GUI 依赖，再执行 `./run.sh`。脚本都会定位项目目录并使用虚拟环境的 Python，不需要手动激活；从其他目录也可通过脚本的绝对路径启动。窗口分为四个区域：

1. **上方权重配置**：副词条、Cost 1/3/4 主词条及小词条权重分为五个标签页，同名主词条在不同 Cost 下可独立编辑；小词条页仅有 Cost 4 固定攻击、Cost 3 固定攻击、Cost 1 固定生命三项。支持导入/导出 JSON 预设、恢复默认、0～1000000 的权重和最多四位小数。修改不会自动覆盖内置配置；需要保留时请导出，下次打开后导入。
2. **中间词条选择**：选择 1/3/4 Cost，主词条候选和 +25 满级值随 Cost 更新；每次切换时 Cost 1/3 默认选攻击百分比，Cost 4 默认选暴击率。固定小词条自动显示 Cost 1 固定生命 2280、Cost 3 固定攻击 100、Cost 4 固定攻击 150，不可手动改写。初始不勾选任何副词条，可选 0～5 个不同副词条并设置档位，切换 Cost 不清空副词条。
3. **下方目标与结果**：设置目标分数（默认 30）、经验弃置回收比例（默认 70%）、打孔器弃置回收比例（默认 30%），以及每个打孔器/每 1000 经验/每件胚子的成本权重（默认分别为 1 / 1.6 / 1，从成本配置读取）。两种回收比例可独立修改。强化和开孔不会失败，材料返还只在玩家主动弃置回收时发生。推荐将“开完剩余词条达标概率”的保守估计与“参考阈值：新胚子达标概率”比较。评分即时更新，策略后台计算，旧输入的结果不会覆盖新结果。
4. **频整器消耗计算**：五条副词条开满后，五个按钮同步显示属性与档位，点击锁定 1～4 条，单次消耗等于锁数。显示当前锁法正提升概率、收益和消耗；列出全部 30 种锁法，并按相同频整器预算比较锁 1～4 条的最佳固定锁法、终态期望升分、实际期望消耗、性价比及下一次的边际收益。概率计算与区域 3 的目标无关，区域 4 使用独立后台队列。

区域3同时显示从零词条开始与当前已激活状态的结果，激活经验、打孔器及回收规则使用用户提供并确认的数据；区域 4 独立以每次锁数计算频整器枚数。源码版独立窗口支持 macOS/Windows；打包的单文件 EXE 面向 Windows 11 x64。

“是否继续激活下一词条”的算法方案见 [激活推荐算法讨论](docs/activation-recommendation-algorithms.md)。已实现网格动态规划与 0 词条基准策略，尚未实现成本感知最优停止。

## 激活策略与成本口径

实现见 [src/echo_strategy.py](src/echo_strategy.py)，成本见 [config/activation-costs.json](config/activation-costs.json)。以下数据由用户提供并确认，不标为官方公示数据；经验及打孔器不再使用占位值。每个解锁等级开孔一次，每次消耗 10 个打孔器；胚子每件计 1，由胚子权重表示其自定义机会成本，不含刷取成本。

**强化和开孔均不会失败，随机的是词条类型与档位。未达标不等于回收；只有玩家主动选择回收才有返还。** 当前成本模型假设未达标且停止投入时选择回收，达标则保留；若只停止投入但保留声骸，不应抵扣下面的返还。

| 解锁等级 | 累计需求经验 | 本阶段需求经验 | 累计实际投入经验 | 弃置返还经验 | 弃置返还打孔器（累计） |
| -------- | -----------: | -------------: | ---------------: | -----------: | ---------------------: |
| +5       |         4400 |           4400 |             4500 |         3000 |                      3 |
| +10      |        16500 |          12100 |            16500 |        11500 |                      6 |
| +15      |        39600 |          23100 |            40000 |        28000 |                      9 |
| +20      |        79100 |          39500 |            79500 |        55500 |                     12 |
| +25      |       142600 |          63500 |           143000 |       100000 |                     15 |

- 经验材料最小单位 500，按累计需求补足，余量保留以抵扣后续升级。实际各阶段新增投入为 **4500、12000、23500、39500、63500**，不能把每段需求单独向上取整后相加。
- 主动弃置回收时，按累计实际投入分别计算：经验返还 70%、打孔器返还 30%（每开一孔消耗 10、回收返 3）。经验向下取整到 500，打孔器向下取整到整数个；在弃置终点取整一次，不逐阶段扣取整损失。保留声骸不回收；胚子本体不返还。
- 已强化声骸作为经验素材使用时按 70% 折算，已在配置单独记录。当前成本统一按回收成经验材料核算，不再叠乘一次 70%，不模拟直接喂声骸、库存与混合素材选择。
- 当前输入未单独设置实际等级，默认已开 $n$ 条对应已投入到 $5n$ 级；已升级但未开孔、额外升级等状态未单独建模。达标即停止，不自动为成功声骸补升到 +25 或开满剩余槽位；评分中的主/小词条仍采用 +25 投影。

- **一次性开五条达标概率 / 开完剩余词条达标概率**：不中途弃置，开满五条后达标的概率；分别从新胚子和当前状态开始计算。同一状态、同一开法下概率是固定值，显示的范围仅来自分数取整造成的计算误差，不是概率本身浮动。
- **有弃置时单次成功率 / 此胚子后续成功率**：每开出一条都按建议判断是否继续，最终达标的概率；前者从新胚子开始，后者从当前状态开始。计算采用分数取整，标为近似。
- **参考阈值：新胚子达标概率**：同 Cost、主词条、权重和目标下，新胚子一次开五条的保守概率估计。当前开完剩余词条的保守估计大于 0 且不低于该阈值时继续，下一条出来再判断。提前弃置会丢掉部分仍可能成功的胚子，不保证最省材料。
- **单个胚子成功或弃置时的平均成本**：处理一个新胚子直到达标或弃置的平均成本，已扣除弃置回收。
- **成功达标时累计成本**：反复换胚子直到成功的平均累计成本，包含此前弃置的投入；预计累计胚子、打孔器、经验消耗按相同口径展示，数量已扣除回收。这些都是平均值，不是保证花费；经验以普通数字显示，不用科学计数法。
- **此胚子后续平均成本**：只处理当前这一件到达标或弃置的后续平均成本，不包含弃置后换胚子直到成功的成本；此前经验和打孔器投入不再次计费。
- **弃置回收比例**：经验和打孔器分别配置，默认 70% 和 30%。配置 `recovery_ratio` / API 参数 `recovery` 只控制经验，`tuning_recovery_ratio` / `tuning_recovery` 只控制打孔器；缺少打孔器回收配置时使用 30%，不沿用经验比例。当前后续成本包含主动弃置时可回收的既有经验及打孔器，因此可能为负；负值表示返还多于后续投入，不代表继续升级会产生材料。
- 成本 = 扣除回收后的打孔器消耗 × 打孔器权重 + **扣除回收后的经验点数 ÷ 1000 × 每1000经验权重** + 胚子件数 × 胚子权重。经验数量仍以实际点数保存和展示，500 经验材料单位与 1000 经验计价单位互不影响。配置的 `default_weights` 同时供 GUI 和策略 API 使用，手动输入/显式参数可覆盖，包含 0。
- **默认成本权重依据**：材料本同时掉落约 12000～13000 经验及 20 个打孔器，取经验中值 12500，令每个打孔器权重为 1、每 1000 经验权重为 $20/(12500/1000)=1.6$，即每 500 经验计 0.8 成本。配置 `experience_weight_unit=1000` 明确该单位；缺少单位的旧配置按每点经验解释并自动换算为每千经验权重（旧 0.0016 → 新 1.6；旧配置经验权重缺省 1 → 新 1000，保持成本数值不变）。API 显式 `experience_weight` 参数及 GUI 输入均按每 1000 经验计。胚子权重保留为可自定义的 1。这只是按供给比例选取的相对折算预设，不代表可兑换价格或精确体力成本；成本权重只改变成本展示，不改变相对概率门槛建议，也不引入成本最优策略。
- 若有弃置时单次成功率为 $p>0$、单个胚子平均成本为 $C$，反复换胚子至达标的预计胚子数为 $1/p$，平均累计成本为 $C/p$。$p=0$ 时显示无法获得，不返回有限期望。
- 假设每次更换相同已筛选主词条的胚子、独立抽样、相同成本及回收规则；未计主词条刷取概率、额外货币和库存约束。

为控制从零状态计算规模，本版使用 1000 格分数网格：将每条增分分别向下、向上取整，得到估算范围的两端；固定概率及成本只是尚未精确求出，而不是在两端之间随机改变。有弃置时的成功率与平均成本按向下取整的模型计算。界面用“估算范围”“保守估计”说明精度，不把近似值称为精确概率。目标默认 30 分；全局最高分对齐到 50 分，但当前主词条可能无法达到该最高分，可降低目标进行探索。

界面仅依赖 PySide6 的 Essentials（Qt Widgets/Core/Gui），不安装此版未使用的大型 Addons 模块。

## 频整器概率与同预算比较

实现见 [src/echo_reconstruction.py](src/echo_reconstruction.py)，完整公式和假设见 [频整器算法说明](docs/reconstruction-algorithms.md)。复用 [config/echo-stats.json](config/echo-stats.json) 中已有重构规则与公示档位概率；无需新增配置 JSON，也不修改用户权重。

- **正提升**：严格超过重构前原始评分，平分不计成功。主词条、小词条、锁定词条固定；未锁定的属性和档位重新随机，原未锁属性可以再次出现，副词条类型仍不重复。
- **单次算法**：枚举类型子集，采用折半分布与前后缀矩求和；十进制原始贡献用有理数转整数严格比较，无区域 3 的分数网格近似。公示概率归一化后以浮点累加，档位与跨次独立为模型约定。
- **收益区分**：期望Δ分包含降分风险；成功时平均Δ分仅在正提升条件下统计；“正收益 / 枚”只计正向部分，不表示可以免费保留旧结果。无限预算下固定锁法首次升分的期望消耗为“锁数 / 单次升分概率”，没有成功路径时为不可获得。
- **相同预算**：固定原始锁法、独立重复，首次超过原始评分即停；否则保留最后一次结果，不假设可以撤销失败。预算默认 4 枚，可设为 0；每个锁数按终态期望Δ分择优。性价比为终态期望Δ分除以期望实际消耗，并展示再增加一次的边际变化。
- **不做线性外推**：锁 2 条洗一次与锁 1 条洗两次均最多花两枚，但分布、提前停手概率、期望收益和实际消耗可能不同；预算页直接比较这些指标，不把单次概率或收益乘次数。
- **建议边界**：所有可执行方案终态期望Δ分均不为正时，建议暂不投入。该建议不包含每次观察结果后重选锁的全局最优策略，也未将材料价值折算成分数；分数不是伤害提升百分比。

## 评分规则

计入**五星 +25 主词条、按 Cost 固定的小词条和已激活的 0～5 条副词条**，不计未激活槽位或套装效果。区域 3 展示三类贡献及总分。

$$
S = \frac{50}{M}\left(x_{\mathrm{main}}w_{\mathrm{main}} + x_{\mathrm{minor}}w_{\mathrm{minor}} + \sum_{i\in A} x_iw_i\right)
$$

- 单条贡献 = 词条数值 × 当前词条权重 ÷ 声骸未对齐最高分 $M$ × 50。
- $M$ = 所有 Cost 主词条候选中最大的“主词条满级值 × 对应权重 + 同 Cost 小词条满级值 × 对应权重”，加上贡献最高的 5 种不同满档副词条的原始贡献。主词条与小词条必须来自同一 Cost，不能分别取跨 Cost 最大值。候选与档位见 [属性配置](config/echo-stats.json)。
- 权重表示每单位词条数值的系数，不再表示满档分值；百分比使用百分点，固定值直接使用原数值。主、副词条分别配置，同名主副词条可以同时计分。
- 主词条输入必须为该 Cost 的 +25 满级值；固定小词条由 Cost 自动确定，无需额外输入。分母不受当前 Cost、主词条或已激活数量影响；未激活副词条槽位贡献为 0。
- 理论最优声骸为 50 分。所有权重均为 0 时，$M=0$，各贡献及总分均返回 0，避免除零。统一倍增全部权重不会改变对齐分数。
- 不按概率、稀有程度计分，分数不代表实际伤害提升百分比。

## 权重

修改 [config/score-weights.json](config/score-weights.json) 中的 `main_stats` 和 `sub_stats`，也可通过命令行 `--weights` 指定自己的配置。所有字段必须完整，权重为非负有限数值，无效属性可设为 0。

本地默认配置及 GUI 导出的 `main_stats` 均以 `"1"`、`"3"`、`"4"` 为键分组，每组包含对应 Cost 的全部合法候选，可分别设置不同权重。`sub_stats` 仍为共用副词条权重。评分及全局最高分使用各 Cost 的独立权重。旧版不分 Cost 的扁平主词条预设仍可导入，其权重会复制到各 Cost 的对应候选中，原文件不会自动改写。

`minor_stats` 保存三项独立权重：`"4"` 下的 `atk_flat`、`"3"` 下的 `atk_flat`、`"1"` 下的 `hp_flat`。三项参与评分和理论最高分，激活策略以主词条加固定小词条作为基础分；固定小词条不占副词条槽位。导入未包含此字段的旧预设时，三项自动补为 0；若提供该字段，则必须完整且只包含上述三项。

内置数值为用户自定义预设，不是官方推荐或任何角色的真实收益权重。修改算法不改动已有权重数值；旧版“满档分值”预设若要保持原相对贡献，需要自行换算为单位数值系数。

## 输入及使用

输入格式见 [examples/echo.json](examples/echo.json)：

- `main_stat`：一个包含 `name`、`value` 的词条对象。
- `sub_stats`：包含 0～5 个词条对象的数组。
- `cost`：可选整数 1、3、4；省略时按主词条名和满级值匹配 Cost，以确定小词条。若匹配多个 Cost 且主词条权重或小词条不同，必须显式提供。
- `name` 支持配置中的准确中文名或统一英文标识；例如“固定攻击”和 `atk_flat`，不接受含糊的“攻击”。
- `value` 使用 JSON 数字；百分比用百分点，例如 10.5 表示 10.5%，不能输入 0.105 或字符串“10.5%”。
- 副词条必须为实际离散档位，副词条之间不可重复；允许与主词条同名。

在项目目录执行 Python 脚本并传入示例 JSON 路径，默认只输出分数；追加 `--details` 输出贡献明细。省略输入路径时从标准输入读取 JSON。默认配置路径相对程序位置解析，不依赖运行目录。

Python 接口：`EchoScorer.from_files().score(echo)`，返回含 `score`、`main_score`、`minor_score`、`sub_score`、解析后的 `cost` 和词条贡献明细的字典。

示例结果取决于当前权重预设，统一按上述公式输出 0～50 分；贡献明细中的 `score` 也为对齐后的分数。

非法输入在 API 中抛出 `ValueError`；命令行将错误写入标准错误并以状态码 2 退出。
